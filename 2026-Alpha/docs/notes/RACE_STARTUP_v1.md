# ETロボコン本番 起動手順 v1

## 1. この手順の対象

地区大会本番で、走行体の全工程と無線通信デバイスのETラリー経路計算を使用する手順です。単体試験用の`rally-drive`は使用しません。

本番では設定ファイル内の工程フラグへ依存しないよう、走行体を`--mission full`で起動します。PC側は3周と現行計算ランナーをコマンドで明示します。

## 2. 起動前チェック

- [ ] 走行体とPCが同じ競技用ネットワークへ接続されている。
- [ ] Raspberry PiのIPアドレスを確認した。
- [ ] PCからRaspberry PiへSSH接続できる。
- [ ] PCとRaspberry Piの両方に、本番で使用する同じ版の`2026-Alpha`が配置されている。
- [ ] `RaceConfig.et_rally_strategy_source`が`"received"`である。
- [ ] TCPポート50000番を、他のプログラムが使用していない。
- [ ] PCのファイアウォールと競技ネットワークで、PCからRaspberry Piの50000番への接続が許可されている。
- [ ] Left／Rightコースを確認した。
- [ ] バッテリー、アーム、カメラ、カラーセンサー、距離センサー、ジャイロ、左右モーターを確認した。
- [ ] PCと走行体の不要なプログラムを終了した。
- [ ] 緊急停止担当者が、走行体側端末で`Ctrl+C`を押せる状態にした。

`ssh -XY`は走行体プログラムの起動と画面表示に使用しますが、ETラリーのStrategy通信を自動的にSSH内へ通すものではありません。通常は、PC側プログラムからRaspberry PiのIPアドレスとTCP 50000番へ直接接続します。

## 3. 使用する端末

同じPC上で端末を2つ開きます。

| 端末 | 実行場所 | 役割 |
|---|---|---|
| 端末A | PCローカル | Hint受信、経路計算、全周回SEQ送信 |
| 端末B | Raspberry PiへのSSH接続内 | 走行体の全工程を実行 |

両端末とも、それぞれの環境にある`2026-Alpha`をカレントディレクトリにします。

## 4. 本番の起動順

### 手順1：PC側を先に起動する

端末Aで実行します。`RASPBERRY_PI_IP`は実際のIPアドレスへ置き換えます。

```sh
python -m wireless_device --host RASPBERRY_PI_IP --port 50000 --et-rally-laps 3 --planner-runner wireless_device/et_rally_runner.py --strategy-log-dir strategy_logs
```

この時点ではRaspberry Pi側のStrategy待受けがまだ始まっていないため、接続再試行ログが出ても異常ではありません。PC側は接続できるまで再試行します。

本番で別の最終計算ランナーを採用した場合だけ、`--planner-runner`のパスを確定済みファイルへ変更します。その場で未検証ランナーへ切り替えません。

### 手順2：走行体側を起動する

端末Bで実行します。Leftコースの場合：

```sh
python alpha.py left --mission full
```

Rightコースの場合：

```sh
python alpha.py right --mission full
```

`configured`ではなく`full`を明示します。これにより、スタート～LAP、Bottle Delivery、ETラリー、ET相撲、FINISHが本番対象として選択されます。

### 手順3：4桁の復号キーを入力する

走行体側端末へ、当日提示された4桁の復号キーを入力します。確認表示を読み、正しい場合だけ確定します。

復号キー入力はデバイス初期化と20ms制御周期の開始前に行われます。PC側には復号キーを入力しません。

### 手順4：キャリブレーション完了を確認する

走行体は次の順で初期処理を行います。

1. アームを上端まで動かす
2. アームを下端まで動かす
3. デバイス値をリセットする
4. タッチセンサー入力を待つ

アームが上下端で停止しない、異音がする、機体が動く、センサー初期化エラーが出る場合は、タッチセンサーを押さず`Ctrl+C`で終了します。

### 手順5：競技開始位置と安全を最終確認する

- [ ] 走行体が指定されたスタート位置・開始方位にある。
- [ ] アームが想定した下端状態にある。
- [ ] コース指定がLeft／Rightと一致している。
- [ ] PC側プログラムが終了していない。
- [ ] コース上と走行体周囲に人や工具がない。

### 手順6：タッチセンサーで走行を開始する

スターターの手順に従ってタッチセンサーを押します。タッチ後に走行処理が始まります。

現在の実装では、走行体側のStrategy TCPサーバーはタッチ後、ミッション開始時に起動します。PC側は接続後も走行を止めず待機し、Hint1とHint2が揃ってから次を行います。

1. 走行体の通信スレッドがHint2を復号する
2. 走行体がHint1と復号済みHint2をPCへ送る
3. PCが3周分の走行指示SEQを計算する
4. PCが全SEQを走行体へ返す
5. 走行体がETラリー開始位置で停止してSEQを待つ
6. 正常受信後、受信SEQに従ってETラリーを走行する

ソケット待受け、復号、TCP送受信はバックグラウンドスレッドで動き、20msの走行制御周期ではブロッキング通信を行いません。

## 5. 正常時に確認するログ

PC側では、少なくとも次の流れを確認します。

```text
Connected to robot ...
Response sent mission=... type=STRATEGY
```

走行体側では、少なくとも次の流れを確認します。

```text
Strategy server listening on ...:50000
Hints queued mission=...
Hints sent mission=... attempt=1
Strategy received mission=... laps=3 commands=...
```

ログの前後関係はスレッド実行により多少入れ替わることがあります。`Strategy received`が出れば、受信したSEQが`RaceContext`へ保存されています。

## 6. 異常時

### 走行体を直ちに止める

走行体側端末で`Ctrl+C`を押します。終了処理が左右モーターを停止し、カメラスレッドを終了します。PC側だけを止めても、既に受信済みの走行体を直ちに停止する操作にはなりません。

### PCへ接続できない

- Raspberry PiのIPアドレスを確認する。
- PC側の`--host`がそのIPと一致するか確認する。
- TCP 50000番とファイアウォールを確認する。
- 走行体側でタッチ前の場合、サーバー未起動なのでPCの再試行は正常。
- 別プロセスが50000番を使用していないか確認する。

### Strategyを受信できない

Hintが揃ってからの上限は5秒です。初回送信と再送2回を試みます。タイムアウト、PC計算エラー、不正SEQの場合はETラリー走行を開始しません。現在、走行体側LOCAL計算への切替は未実装です。

### 復号キーを間違えた

走行開始後に修正する運用はありません。タッチ前に`Ctrl+C`で終了し、走行体プログラムを再起動して正しいキーを入力します。

## 7. 競技終了後

1. 走行体が停止したことを確認する。
2. 走行体側端末を`Ctrl+C`で終了する。
3. PC側端末も`Ctrl+C`で終了する。
4. 走行体側の自動`run_logs`を保存する。
5. 必要に応じて`--logfile`で指定した機器ログを保存する。
6. PC側`strategy_logs`のHint、選択周回数、返信SEQを保存する。
7. 実走結果、異常、手動操作、コース状態をログと対応付けて記録する。

## 8. 本番直前に使用しないもの

- `--mission rally-drive`：ETラリー走行単体試験用
- `--strategy-file`：固定SEQによる通信試験用
- `et_rally_strategy_source="file"`：固定plan互換試験用
- 未検証の`--planner-runner`：計算プログラム比較用
- `--check-tree`：構成確認用であり実走しない

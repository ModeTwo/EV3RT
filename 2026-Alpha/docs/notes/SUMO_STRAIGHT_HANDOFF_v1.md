## ②の実動作（校正JSONなし）

1. ジャイロ目標方位に沿って既定1000mm・出力80で直進。カメラで黒ボトルの位置を観測・記録するが、直進中の画像で操舵しない。
2. 規定距離後に停止し、画像を使って正対。停止後の検出が得られない場合、条件を満たす走行中履歴があれば一度再探索し、その後も確定できなければ失敗。
3. 前進しながら距離センサー生値を読み、`0 < raw <= 80` が1回あれば捕捉成立と扱う。上限は既定500mm・出力80。成立後は再判定しない。単発値は物理的なキャッチ成功の保証ではない。
4. 正対方位が緑方向と判定され、かつ捕捉成立なら、捕捉したまま初回直進の目標方位へ旋回する。非緑方向なら旋回しない。未捕捉で500mmに達した場合も旋回せず押し出し距離へ進む。緑方向判定は正対方位と緑方位の角度のみに基づく簡易判定で、位置や経路の幾何判定はしない。緑への不侵入は保証しない。
5. 指定された追加距離を、旋回後の実際の向きで押す。成功条件は距離到達であり、ボトルの土俵外への到達を確認していない。
6. 押しの実走距離を出力80で後退。捕捉後に旋回した場合は正対時の方位へ逆旋回し、捕捉接近で走った距離を後退して停止する。

## 単体実行例（Pi）

```bash
cd /home/pi/EV3RT/2026-Alpha
pypy3 alpha.py left --mission sumo-push-route-test --sumo-distance-mm 1000 --sumo-power 80 --sumo-push-distance-mm 300 --no-preview --sumo-push-execute
```

`left` / `right` は実コースに合わせる。300mmは捕捉後の**追加押し距離の指定例**で、最適値や土俵外到達距離の保証ではない。`--sumo-push-execute` がなければ正対・角度判断後に終了し、捕捉や押し出しは行わない。`--sumo-push-calibration` を付けると別の校正あり経路になる。依存関係・ハードウェア初期化はPiの既存環境を使用する。

## ①・③・統合担当への受け渡し

- ①出口：②が始める車軸位置・姿勢、走行可能距離、ボトル配置範囲、左右コース、ジャイロ基準を現場で確定する。デリバリー後にジャイロを勝手に再ゼロせず、全体の基準と一致させる。
- ②入口：`build_sumo_push_tree(context, config)`。単体は`tree_builder.py`から呼ばれる。`context.sumo.bearing_reference`は`RegisterSumoBearing`で初期化済み、gyro scale・モーター・距離計・カメラ・距離センサーが利用可能であること。単体の初期床面方位はLEFT 270°、RIGHT 90°、初回直進のジャイロ目標は開始基準0°。
- 結合時、同builderは `mission_mode != sumo-push-route-test` なら基準からLEFT −90°／RIGHT +90°の目標を設定する。ただし、これは**目標値の分岐が存在するという意味**であり、①→②→③が既に結合・動作確認済みという意味ではない。実装時に方位の符号、全体基準、床面方位、姿勢、`config.sumo_push_execute=True`、押し距離の明示設定を検証する。特に通しの床面方位登録と単体のLEFT/RIGHT初期値は異なる。
- ②出口：正対完了位置を目指した概算の復帰後、車体は概ね正対時の方向。旋回精度、車軸位置、ボトルの残留位置は保証されない。成功ステータスは規定の処理完了であり、捕捉・押し出し成功の証明ではない。③は位置・方位を実測してから接続条件を決める。
- コード構成：`tree_builder.py` → `features/sumo_push_tree.py` → `features/sumo_push_route.py` → `features/sumo_relative_push.py`。初回直進・画像正対は `features/align_sumo_bottle.py`。既存の `phases/et_sumo.py` や通しのミッションが今回の②と同一とは限らない。

## 停止条件・記録・評価

録画/カメラ失敗、各工程の時間超過、画像喪失・正対失敗、センサー無効、直進/後退で1秒間に2mm以上進まない、逆走判定、子動作失敗や例外などでは失敗停止する。押し中の4°超過や捕捉後の測距再判定だけでは停止しない。終了後のステータス・ログを確認する。

`run_logs/` に実行ログ、`sumo_align_runs/` にraw・検出表示AVI、frames CSV、summary JSONを保存。重要な記録は `SUMO_ALIGN DRIVE`、`SUMO_RELATIVE ANGLE`、`CAPTURE_CONFIRMED_MOVING` または `CAPTURE_NOT_CONFIRMED_CONTINUE`、`PUSH_ACTUAL_BEARING`、`BACK_START`、`BACK_TURN`、`BACK_COMPLETE`、`SUMO_ALIGN FAILED`。`BACK_COMPLETE` は復帰動作の完了記録であり、正確な位置到達や押し出し成功は現場で確認する。

ユーザーの実機報告では正対後の500mm/P80の捕捉接近は確認済み。直近の復帰を含む3走行のログでは接近開始〜BACK_COMPLETEが8.291 / 11.079 / 8.858秒、平均9.409秒（RIGHT・押し300mm）。位置復帰精度、左右・配置全域、緑領域回避、①③との結合は未検証。各条件の成功率を断定しない。

## 統合担当が次に行うこと

1. 共有ブランチと統合先の差分を比較し、相撲以外の変更も含む依存関係を確認する。
2. ①出口・②入口・②出口・③入口の実測位置と向き、各許容範囲、左右、緑エリアとボトルの位置を共有する。
3. 全体ツリーで①→②→③を結合し、ジャイロ基準登録と有効化、押し出しの実行設定、失敗時の分岐、カメラ所有権を確認する。現在の単体用コマンドは自動的に通し走行へ組み込まれない。
4. ボトルなし・あり、左右、緑方向あり・なし、捕捉できない場合、復帰後の位置差を記録し、段階的に実機確認する。

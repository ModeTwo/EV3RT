# 規定距離接近→力士ボトルへ正対→停止 v1

## 今回の相撲プログラムの読み方（2026-10-31 可読性整理）

元のfeaturesの考え方に合わせ、処理順と各動作の責務を分けた。alphaは初期化/引数/タッチ/周期、tree_builderはミッション選択、AlignSumoBottleは規定直進/画像正対、RelativeAlignAndPushは正対後の捕捉/戻り/押し。今回の通常コマンドは較正JSONなしのsumo-push-route-test。

読む順序は`tree_builder.build_mission_children`→`sumo_push_route.build_sumo_push_route`→`sumo_relative_push.build_relative_push`→`RelativeAlignAndPush.update`。正対前は親updateへ委譲。正対後は計測/終了優先判定→状態別動作→必要時のみ共通前進、の順で1周期ずつ動く。

相対方式の状態別動作は `_update_capture_approach`（候補接近）、`_update_stationary_confirmation`（捕捉/戻り後の停止確認）、`_update_return_turn`（戻り旋回）、`_check_push_capture`（押し中証拠）、`_update_post_push_recording`（終了録画）。`_drive_forward`に逆行/方位/停滞の確認と前進出力をまとめた。ログのNC_状態名は互換のため維持（較正なし方式を表す）。

AlignSumoBottleも規定接近/待機/画像旋回/観測/録画終了をメソッドへ分けた。SumoBlackDetectorは画像候補と同一対象の追跡、VisualTurnPolicyは画像/gyroからの出力判断、VisualBottleTurnはモーターIO、SumoAlignRecordingは動画/CSV/summary保存。センサー静止測定とキー操作、旋回/捕捉単体試験、較正方式は補助機能として別ファイルに保つ。

設定を読む入口：`sumo_align_settings.py`は規定直進/画像正対、`sumo_relative_push_settings.py`は捕捉/戻り/押し、`sumo_catch_settings.py`は共用の方位4度・停滞等、`sumo_sensor_settings.py`は静止測定、`sumo_turn_test_settings.py`は旋回試験。引数はalphaのsumoブロック。数値・閾値・既定値・例外条件は変更していない。

動作順・センサー読取順・距離優先停止・候補で制動して停止中確認・戻り後の補正なし/実停止方位で押す・押し中4度停止・記録項目/ログ・alphaライフサイクルを維持した。表記整理だけのファイルはdocstringを除くAST同値、主要2クラスは改修前後の偽IOトレースと既存テストで照合する。元のcapture_sumo_bottle_camera等は参照資料として読み、今回の旧ミッションには変更を加えない。




`alpha.py`から既存の機器登録、アーム上下初期化、ResetDevice、タッチ開始、20ms制御を通して呼び出す専用ミッション。単独スクリプトへのalphaコピーではない。



## 実行



2026-Alpha直下で実行する。



```sh

python alpha.py left --mission sumo-align --sumo-distance-mm 1000 --sumo-power 80 --no-preview

```



右コースは`left`を`right`にする。プレビューは既定でON。表示する場合は`--no-preview`を外す。プレビューによる処理速度低下は別途測定する。



配置は「撮影試験の直進開始地点」に手動で合わせ、ロボットの初期前方を直進方向にする。従来sumoの開始位置への移動、100mm後退、探索前進などは呼ばない。初期方位は既定0度で、必要なら`--sumo-initial-bearing 270`などで指定できる。この値は方位基準の登録であり、指定方位への初期旋回ではない。



今回の配置G0=1310mm、D=1000mmは指定値の差が310mmだが、停止実距離は未測定。旋回中のアームとボトルの接触、惰性を確認してDを決める。PWM80は速度mm/sを意味しない。



機器を開かず、実行木だけ確認する場合：



```sh

python alpha.py left --mission sumo-align --sumo-distance-mm 1000 --sumo-power 80 --check-tree

```



正対後も既存TheEndで停止状態を保ち、プログラムはCtrl+Cで終了する。失敗時はalpha既存の停止経路へFAILUREを返す。



## 処理と責務



1. `features/align_sumo_bottle.py`：直進、停止待ち、画像確認、旋回、再確認の状態を管理。

2. `RunByGyro`：距離関数モードに一定0度を渡し、開始時方位で直進。毎周期の出力上限とブレーキ解除は既存実装を利用する。PWM80なら補正余裕は±20。PWM100では補正余裕が0になる既存仕様に注意。

3. `IsDistanceEarned`：開始時のオドメトリを保存し、指定距離到達を前進出力より先に判定。RunByGyroにも同じ距離上限を渡す。

4. `features/sumo_black_detector.py`：推奨full_hybrid検出。640x480中央16:9→320x180。HSV S≤120・V≤60、7x7 open/close、面積150以上、extent .45以上、幅176以下。最大の原条件適合輪郭に、高さ12以上・幅/高さ1.5以下を追加。初期全縦範囲→96px追跡帯→失敗時同一フレーム全体再探索。2新規フレーム確認、2欠測で再獲得。

5. `Video`：既存のカメラ処理スレッドから専用観測を配信。直進中も検出するが、画像操舵は行わない。撮影フレームID、ホストread終了時のmonotonic時刻、その直後に読んだ補正済みジャイロ・距離を一括で配信。ハードウェア露光時刻ではなく、カメラ内部のバッファ遅延は未補償。

6. `VisualBottleTurn`：2026-10-28から通常sumo-alignの旋回を画像＋ジャイロ制御へ変更。純粋計算の`sumo_visual_policy.py`とIOの`sumo_visual_turn.py`を分離。共通EncoderSpinToBearingは変更しない。画像右は両コースとも物理時計回り。



直進停止後は0.3秒待って新しい読取セッションを開始する。旋回中は同じセッションの新規画像で減速・制動し、停止確認後は0.04秒待って別セッションで最終正対を再確認する。走行中・旋回中の画像を最終成功確認に数えない。既定では検出側2フレーム確定に加え、正対範囲内の確定観測を2回確認するため、通常は停止後の画像を最低3枚要する。



目標中心は160px、許容±8px。`--sumo-target-cx`でキャッチ機構とカメラの位置ずれに合わせて変更できる。正対確認時に撮影時から方位が2度を超えて動いた画像は成功に数えない。必要時は最大20度ずつ、最大5回旋回し、毎回停止後に再確認する。到達しなくても補正回数上限を成功扱いしない。



## 終了条件



- 成功：新規の確定観測で正対を確認し、左右出力0・ブレーキON。`context.sumo.bottle_aligned=True`と正対方位を記録。

- 捕捉・押し出しフラグはFalseのまま。アーム操作、捕捉、押し出し、復帰走行へ進まない。

- 失敗：直進15秒、停止後の安定観測3秒、各旋回4秒、全体40秒の上限。または補正5回終了後も不一致。停止して理由をログへ出す。

- 画像年齢0.4秒以内のみ使用。同一フレームの再読込は確認回数に数えず、0.5秒超の間隔は連続確認を解除する。

## 2026-10-28 画像による旋回中の減速・制動と補正縮小



実行は既存alphaのまま。Piで`pypy3 alpha.py right --mission sumo-align --sumo-distance-mm 1000 --sumo-power 80 --no-preview`。直進パワー80と旋回パワー75/50は別設定。



1. 撮影時の横ずれを`e = cx - target_cx - 7.5*(現在gyro - 撮影時gyro)`で現在へ補償（角度差は±180度へ正規化）。7.5px/度は今回の実測傾向から置く暫定近似。旧pixel_bearingによる角度指令は通常sumo-alignでは使用しない。遠方・大角度での正確なカメラ較正を意味しない。

2. 直近80msの角速度ピークを保持し、`e_stop = e - 角速度*0.10秒*7.5`で制動を先行する。残角が予測停止角＋0.5度以下、予測中央通過、中央±8px、補正量上限でブレーキ。0.10秒は暫定値で、実機調整が必要。

3. 残角12度以上かつ制動余裕があり、60ms以内のvalueマスク確定画像なら75。それ以外は50。残角5度以上で80ms動きが出ない場合のみ、最大40msの75始動補助を1旋回1回まで許す。小角度と行き過ぎ後は75を使わない。残角4度以内または反転後は50を20ms駆動し、120ms以上制動・観測する。駆動時間の実効値は制御周期・IO遅延に依存する。

4. 画像年齢120ms超、欠測、未確定、別セッションなら即ブレーキ。見失い600msで失敗。旋回中のtrack_id変化も失敗。予測だけで見失った対象へ旋回し続けない。

5. ブレーキ後120ms以上、直近約120msのgyro変動0.6度以内（3標本以上、100ms以上をカバー）、かつブレーキ後に撮られた確定画像を要求する。静止判定はgyro依存であり、エンコーダや物理的な完全停止の保証ではない。

6. 静止画像の誤差符号が許容帯＋2pxを超えて反転したら、次の補正上限を20→10→5→2.5…度（下限0.75度）へ縮小。左右から得た方位の区間が有効なら、その中点までを追加上限とする。反転前に必ず制動・静止確認し、反転後は75を無効化。マスク源切替では区間・符号履歴を破棄し、既に縮めた上限は維持する。

7. 1回の旋回20度、逸脱28度・4秒、16駆動パルス、反転5回を上限とし、既存の補正5回・全体40秒も維持する。上限到達は成功にしない。最後は別セッションの新しい静止確定画像2回で正対を判定する。



CSVに`visual_*`列（補償誤差、予測誤差、角速度、出力、画像年齢、区間、反転回数等）を追加。summary.jsonのdetails.visual_turnsに制御標本と実際のAPI指令時刻を記録する。記録は有界メモリ＋既存非同期保存で、制御からディスクへ直接書かない。API指令時刻は実モーター応答時刻ではない。



PCでは既存34件、新制御22件（遅延・惰性を置く合成12ケースと両コース通常ツリーを含む）、記録6件、従来診断21件を確認する。合成モデルの収束は実機性能の証明ではない。Pi配備・実機試験は未実施。カメラのtはread終了時刻なので、露光・カメラ内部バッファ遅延は補償できない。既存動画の再生だけでは変更後の閉ループ旋回成功率・所要時間は検証できない。



次はプレビューOFF、同じ配置・D/Pで中央・左右を各3回。CSVと動画で最初の中央通過前の制動、停止後誤差、最終正対成功、正対所要時間、反転回数を比較する。75の有効性・50の始動不足、画像遅延が大きい場合の失敗を含めて評価する。キャッチ・押し出しへ進めない。

## 2026-10-31 ボトル位置と距離値の対応試験（sumo-sensor-test）

```sh
pypy3 alpha.py left --mission sumo-sensor-test --sumo-sensor-label inside --sumo-sensor-sec 5 --no-preview
```

## 1. 自由時間（会場の床、較正台）
カメラに触れた・ぶつけた・向きが変わったかもしれないときだけ行う。迷ったら行う（5分）。

1. **較正台の画像を3枚撮る**。1枚ごとに置き直し、アームは上げた状態で撮る。台が床でガタつかないことを確かめる。ロボットで:
   ```
   python3 et_rally_camera_capture.py --tag jig --count 1
   ```
2. **PC で較正し直す**:
   ```
   python wireless_device/et_rally_camera_calib/recalibrate_day.py --set-default
   ```
   - ばらつきの警告が出たら撮り直す。
   - 問題なければ commit・push し、ロボットで `git pull`。
   - 較正台で戻せるのは大きなずれまで。向き・左右・前後の細かいずれは、2章の試走で詰める。

## 3. 本番
**注意（11/14 夜の時点）: 本番の起動 `python alpha.py <course> --mission full` では、次の3つがまだできない。**
- **計画**: `full` は、PC の旧い計算からステップの列だけを受け取る。新しい道具の計画（`exit`・ゲートの位置つき）は、ファイルを指定したとき（`--rally-plan-path`、`rally-drive` だけ）しか走れない。持ち時間での切り上げ、脚を見る引き直し、ガレージでアームを下ろす目印も効かない。
- **カメラ**: `full` では本体（ほかの工程の QR・ボトル・相撲）がカメラを開いている。ETラリーのカメラの子プロセスと取り合いになるので、スタートの取り込みと走行中の補正を入れていない。
- **オプション**: `full` では `--rally-*` を付けられない。設定は RaceConfig の既定値で決まる（カメラを使わないものは 11/14 に既定値にした）。

## 参考: 今の既定（2026-11-14）
- 円弧・直進は出力100、円弧の先読み `lead_sec` 0.08。脚とのすき間が2.5cm 未満の直進は、出力の上限92。
- 経路の道具:
  - すき間は3cm から。3cm で通れない配置は、3cm のまま全部のゲートで斜めの通過を試す（narrow_oblique_grid）。それでも通れなければ2.5→2.0→1.5cm。
  - 選んだすき間で作れなければ、次のすき間で作り直す。
  - 最後の周の黄は、すき間2cm 以上の通り方だけ。
- 計画の独立検査: `wireless_device/et_rally_curve_proto/check_plan.py <plan> wireless_device/et_rally_curve_proto/params_day.json`。day_route.py は最後に自動で行い、結果を表示するだけ（NG でも走らせる）。
- スタートの取り込み:
  - 見えたもの（点+マーカー）が2つ以上なら、下向きも当てはめて、前後・左右・向きを入れる（2つのときは、前後に離れた2つの間隔で下向きが決まる。11/14）。
  - 当てはめに失敗したときだけ、前に床で当てはめて覚えた下向きで写し直し、向きと左右だけを入れる（前後は計画のスタートのまま）。
  - 測った画像を最大6枚、カメラの記録のフォルダに残す（`start_*.jpg`）。
- 既定値になった設定（11/14、オプションなしで効く）: ハブのジャイロの測り直し2秒・振動待ち1.0秒、短い直進の手前止め15mm・止め始め18mm、アームの出力40・260°・走りながら上げる・上げる秒0.9。
  - 試験のコマンドからは、これらのオプションを省いてよい。
  - 付けたままでも、同じ値なので問題ない。

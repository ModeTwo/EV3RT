# 小角度旋回・制動特性の計測 v1

## 目的と範囲

第1段階の実機9回では、画像の換算と実機の旋回・制動を分けて測る必要があった。今回はalpha.pyから呼ぶ専用featuresの診断ミッションsumo-turn-testを追加する。既存の初期化、デバイス登録、IMU、ResetDevice、タッチ開始を保持し、ミッション部だけを計測へ切り替える。

前進ノードを作らず、既存EncoderSpinToBearingを1回実行する。共通のエンコーダ旋回・ジャイロ仕上げ・停止処理、通常sumo-alignの動作は変えない。車輪の逆方向駆動でその場旋回を指令するが、実機の滑りや並進がゼロになることは保証しない。②旋回画像による制動、③縮小補正はまだ実装しない。

## 実行

Raspberry Piで、まずツリー確認（走行しない）：

```bash
cd /home/pi/EV3RT/2026-Alpha
pypy3 alpha.py right --mission sumo-turn-test --sumo-turn-angle 5 --sumo-turn-power 75 --check-tree
```

実機計測：

```bash
pypy3 alpha.py right --mission sumo-turn-test --sumo-turn-angle 5 --sumo-turn-power 75 --no-preview
```

- 正は物理的な時計回り、負は反時計回り。right/leftの指定でこの符号を反転しない。
- 角度の大きさは1～20度、出力は整数20～80。既定は5度、75。
- --sumo-turn-hold-secは旋回ノードの完了後に観測する時間で0.5～3秒、既定1秒。比較中は同じ値にする。
- 録画準備と約0.3秒の基準観測を終えてから旋回する。基準観測でセンサー値が安定しなければ開始しない。
- 旋回ノード完了後は追加の向き補正をせず、ブレーキをかけたまま指定時間を観測する。直近約0.2秒のジャイロ変動幅1.1度以内・左右エンコーダ変動幅各1度以内を安定条件とする。これはセンサー上の条件であり完全な物理停止の証明ではない。
- 旋回4秒、初期カメラ待ち5秒、全体20秒などの上限あり。開始方位から指定角度の絶対値＋12度を超えた場合も停止して失敗とする。
- SUMO_TURN_TEST RECORD CLOSEDとTheEndを確認してからCtrl+Cで終了し、ファイルを回収する。SUCCESSは計測が終了した意味で、指定角度の精度合格・ボトルへの正対成功ではない。

既存の終了時停止確認タイムアウトは今回の改修対象外。正対試験で見られた同現象が出た場合は、今回の計測結果と分けて記録する。

## 最初の実験条件

前回と同じ床・カメラ・車体構成・負荷を維持する。空いた場所で前進させずに実施する。画像の見え方も比較する場合は、接触しない前方に目印やボトルを固定する。照明を変更する必要はない。毎回、床の印などで同じ位置・向きへ戻してから起動する。自動で元の向きへ戻す動作は含めない。

まず次の4条件を各3回、計12回。条件順は75で正/負、その後50で正/負とし、同じ初期位置へ戻す。最初は75で現行の応答を確認してから50と比較する。

| 条件 | angle | power | 回数 |
|---|---:|---:|---:|
| CW75 | +5 | 75 | 3 |
| CCW75 | -5 | 75 | 3 |
| CW50 | +5 | 50 | 3 |
| CCW50 | -5 | 50 | 3 |

```bash
pypy3 alpha.py right --mission sumo-turn-test --sumo-turn-angle -5 --sumo-turn-power 75 --no-preview
pypy3 alpha.py right --mission sumo-turn-test --sumo-turn-angle 5 --sumo-turn-power 50 --no-preview
pypy3 alpha.py right --mission sumo-turn-test --sumo-turn-angle -5 --sumo-turn-power 50 --no-preview
```

必要に応じて次に±3度・±10度を追加する。出力50では主駆動も仕上げも50となる。一般に仕上げ上限=min(60,power)、仕上げ下限=min(50,power)。従来クラスの停滞時の出力引上げも、この試験のpowerを超えない。動かずタイムアウトした場合も、計測上意味のある失敗として保存する。

## 保存と評価

sumo_turn_test_runs/にraw AVI、検出表示AVI、フレームCSV、summary JSONを保存する。名前の時刻はUTC。録画処理は既存の非同期サービスを再利用する。

summaryのdetailsに保存するもの：

- requested_angle_deg / actual_angle_deg / final_error_deg：指令角度、観測終了時の実方位差、符号付き誤差。
- completed_gyro_deg / final_gyro_deg / rotation_after_completion_deg：旋回ノード完了時と観測終了時の差。
- turn_duration_sec：開始から旋回ノード完了まで。
- sensor_settled_at_end：観測終了時のセンサー安定条件。
- control_samples：制御周期の時刻、ジャイロ、左右エンコーダ、工程、旋回段階、最後の出力指令。
- motor_commands：成功して戻ったモーターAPIへの出力/ブレーキ呼出し、左右、時刻、工程、旋回段階。物理的な受理時刻や実出力のフィードバックではない。

API指令を観測するラッパーは、この診断が旋回子ノードをtick/stopする間だけ装着し、例外時も元のruntime参照へ戻す。他ミッションへ残さない。制御ループでファイルへ書き込まず、上限付きのメモリ記録を終了時に非同期録画サービスへ渡す。CSVではtest_control_gyro_deg、test_left/right_count、test_left/right_commandを追加。カメラ姿勢値と制御サンプルは異なる時刻なのでcontrol_sample_monotonic_secも参照する。

比較するのは、指令角度に対する誤差、完了後に回る量、所要時間、動き出し、仕上げの出力引上げ・往復、左右差。センサー分解能とサンプル間隔の影響があるため、1回だけで最適値を確定しない。

PCへ回収する例：

```powershell
scp -r pi@192.168.137.78:/home/pi/EV3RT/2026-Alpha/sumo_turn_test_runs .
```

## 検証状況

PCで診断18件、既存追跡/正対34件、録画6件を検証。初期化/タッチ開始、前進なし、左右コースの符号、カメラ待ち、センサー安定待ち、中断・例外・時間上限・角度上限・録画失敗時の停止、観測終了後の計測値、summaryへの履歴保存を対象とする。PiのPyPy実行・実機の停止性能は未検証。

## 2026-10-28 12回の計測後：安定判定の窓を修正

11回のsummaryを受領し、4・6・9回目のFAILUREはジャイロ・エンコーダの変動超過ではなく、窓内だけの抽出で実観測長が約0.141～0.150秒に短くなった判定不具合だった。元のsummaryの結果は書き換えない。12回目は受領した4ファイルが全て0バイトで未確認。

修正版では0.2秒境界の直前サンプルも含める。3サンプル以上・実観測長0.2～0.35秒・最大サンプル間隔0.15秒以下を満たしたうえで、従来と同じジャイロ変動幅1.1度以内・左右エンコーダ変動幅各1度以内を判定する。summary.details.stability_windowにサンプル数、観測長、最大間隔、各変動幅と判定を記録する。動きを許容する閾値の緩和ではなく、時刻の選び方の修正である。記録が疎すぎる場合は安定と判定しない。

通常sumo-alignの旋回や出力設定は変更しない。この修正のPCテストは診断21件と既存追跡/正対34件・録画6件を対象とする。実機での修正版の再確認は必要。

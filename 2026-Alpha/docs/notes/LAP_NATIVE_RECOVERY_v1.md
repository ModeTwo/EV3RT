# devTK通常VideoThreadによるLAP黒線復帰

2026-11-14。devTKからの作業ブランチ `codex/devtk-lap-camera-recovery`。LAP単体と本番のLAPは同じbuild_start_to_lap_gateを使用する。スタートから4450mm未満はdevTK距離プロファイルの出力を用い、4300mm以降ボトル色の観測、4350mm以降の線画像観測、4450mm以降の160px基準補正を行う。160pxは未較正の仮値。通常VideoThreadがカメラを1台だけ所有し、画像とボトルは同じフレームから観測する。画像はキューから保存し、処理時間とドロップをログに残す。

青→黒成立時は黒検出から投影200mm、未成立のフォールバックは推定ゲートから150mmを基準方位で進む。接近完了はcontextへconfirmed/fallbackとして明示し、ATが接近済みの場合だけ従来の設定距離（既定300mm）を繰り返さず、停止・色確認・TO受渡しは実行する。AT単体・hint2系は従来どおり。未検知色のBLUEは検知成功と別にログを出す。

PC: 模擬デバイスの4450mm未満16点で左右・出力/目標角一致、160/186票、暗青→黒、PWM40と200mm、AT二重走行防止、通常VideoThread同一フレーム/画像保存、LAPと通常ミッションのツリー構築を確認。実機のUSB切断が解消したか、撮像負荷、走行とボトル捕捉は未検証。Piへは `work/devtk-lap-production-v1/send_production.py` を使い通常の2026-Alphaに差分を配置する。ログと画像は同collect.pyでSHA照合後Pi側を削除。従来の試験用別フォルダは使用しない。

## 走行距離更新の診断（2026-11-14）

通常のPlotterが読み取った左右モーターの回転角を再利用し、約0.2秒ごとに `ODOMETRY_SAMPLE` を記録する。right_deg/left_degは積算回転角（度）、right_rpm/left_rpmは前回出力からの平均回転速度、distance_mmは小数を含むPlotter累積値。read_mono_secはPi側で値を読んだ時刻、unchanged_secは最後に値の変化を観測してからの秒数であり、ハブがデータを生成した時刻や通信状態の保証ではない。走行指令と停止条件は変更していない。停止中や直進以外で値が一定な場合もあり、数値だけで異常と断定しない。

PCではモックモーターで追加読み出しがないこと、回転角・RPM・累積距離・無変化時間を検証。実機および6GHz切断との同時発生は未確認。

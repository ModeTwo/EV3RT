## 1. 会場に着いたら（カメラ）
カメラの向きが変わっていなければ、この章は 1-3 の床での確かめだけでよい。

1. **較正台の画像を3枚撮る**（1枚ごとに置き直す。アームは上げた状態）。ロボットで:
   ```
   python3 et_rally_camera_capture.py --tag jig --count 1
   ```
2. **PC で較正し直す**:
   ```
   python wireless_device/et_rally_camera_calib/recalibrate_day.py --set-default
   ```
   ばらつきの警告が出たら、撮り直す。問題なければ commit・push し、ロボットで `git pull`。
3. **床で確かめる**（必ず行う。較正台の下向きは、撮るたびに約1°ずれることがある）。スタート位置にまっすぐ置いて:
   ```
   python alpha.py right --mission rally-drive --rally-gyro-hub-recal-sec 2 --rally-gyro-drift-settle-sec 1.0 --rally-start-pose on --rally-camera-log 5 --rally-camera-exposure 30 --rally-arm-stop-ticks 3 --rally-arm-power 40 --rally-arm-travel-deg 260 --rally-plan-path robot_program/tests/plan_test_arm_only_1111.json
   ```
   - ログの `start pose:` で、点が1つ以上見えていて（`dots>=1`）、計画のスタートからのずれが数mm〜1cm程度なら合格。
   - 数cmずれる、または位置が出ないときは、較正台を置き直して 1 からやり直す（`--set-default` で変えた分は元に戻す）。
   - 合格した回の下向きはロボットが覚え、点が見えない回の走行中の補正に使う。

## 2. ゲートの配置が分かったら（経路づくり、PC）
ゲートは公式の座標 `GX-Y` で、各ゲートの2つの点を書く（右コースの図: Y1 が上、X5 が左。左コースの図は左右が逆で X1 が左）。
左コースのときは `--course left` を付ける（計画は同じで、走るときに向きだけ逆になる）。
例: seed 9392783 は `--red G3-3,G4-3 --blue G2-3,G2-4 --yellow G2-1,G3-1`。
```
python wireless_device/et_rally_curve_proto/day_route.py --red G2-1,G3-1 --blue G2-3,G2-2 --yellow G3-2,G4-2 --name day_r1 --full-sec 300
```
- 1段目（速い設定）で経路を作る。1配置おおむね10〜60秒。
- `--full-sec 秒` を付けると、2段目で斜めの通り方を細かく試し、速い経路が見つかったときだけ差し替える。数十秒〜6分ほどかかる。時間がなければ外す。
- 結果は `robot_program/tests/plan_<name>.json` に保存され、走らせるコマンドも表示される。commit・push し、ロボットで `git pull`。
- 「1段目で経路が作れなかった」と出たら、ゲートの点の書き間違い（となり合う点か）を確かめる。

3. 黄ゲートを抜けた後のガレージへの最後の走りで、アームを出力20で下げる（自動）。

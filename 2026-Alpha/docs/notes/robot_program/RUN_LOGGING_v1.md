# 実行ログの自動保存

## 普段の実行方法は同じ

```sh
python alpha.py right --mission lap
```

実行ごとに `2026-Alpha/run_logs/run_日時Z_PID_識別子.log` を作成する。開始時に `[run log] Recording: ...`、終了時に `[run log] Saved: ...` と保存先を表示する。ファイル名の日時はUTCで、JSTより9時間前の表示になる。

実行終了を待ってからまとめて書くのではなく、実行中から1行ごとに保存する。正常終了、Ctrl+C、SIGTERMによる終了、Python例外時も終了状態を記録してファイルを閉じる。電源断/SIGKILLでは終了行は書けないが、それまでflush済みのログは残る可能性がある。強制断での永続化は保証しない。

## 保存される内容

- Pythonの標準出力と標準エラー。画面にも従来どおり表示する。
- 各行のUTC時刻、記録開始からの秒数、stdout/stderrの区別。
- `profile` のnominal/target/actual/error/xte_est/FF/PID/PWMなど、既存の表示内容。
- 終了結果。通常のPython例外ではスタックトレースも記録する。

端末表示だけの自動折返しやスクロール履歴の上限には影響されない。ANSIの色指定はファイルから除去する。C拡張がOSのファイル記述子へ直接書く出力や、取得前のimportエラーなど、Pythonのsys.stdout/sys.stderrを通らない出力までは対象にしない。

既存の `--logfile` はETRobo機器側のログで、今回の画面ログとは別。これを指定しなくても画面ログは保存する。

## 次回ログを渡す方法

実行後に表示された `.log` をそのままPCへコピーして添付する。Pi上で探す場合は2026-Alphaで `ls -lt run_logs`。途中の文字を端末から選択してコピーする必要はない。

カメラ録画と照合するときは、PCとPiの時計が合っているとUTC時刻で対応付けやすい。運転開始のタッチ待ち時間もログへ残る。

## Gitへ含めない

`2026-Alpha/.gitignore` に `/run_logs/` を設定している。通常の `git add .` やコミット/pushではログが対象にならない。除外設定もPiへ転送する。ログを別の追跡対象フォルダへコピーしたり、`git add -f`で強制追加したりしない。

既存ログの上書き・自動削除は行わないので、不要になったログは後で手動整理する。

## ファイル保存に失敗した場合

最初に保存先を作れない場合は、走行を開始する前にエラー終了する。走行中に容量不足等で保存できなくなった場合は、制御処理を中断せず、保存停止の警告と最後に `INCOMPLETE` を表示する。そのファイルは完全なログではない。

## 配備するファイル

- `alpha.py`
- `robot_program/services/run_log.py`（新規）
- `.gitignore`（新規。隠しファイルなので転送漏れに注意）

走行体制御、PIDゲイン、工程順序は変更していない。`alpha.main()`を直接呼ぶテストには自動保存を追加せず、通常の `python alpha.py ...` の入口から有効になる。標準ライブラリのみで動作する。

確認: `python -B robot_program/tests/run_logging_tests.py`。

# LAPカメラ復帰とボトル接近

通常の `build_start_to_lap_gate` は、profile走行のLAPと全体走行で同じカメラ復帰を使う。hint2系とlegacy経路は対象外。通常VideoThreadから画像を共有し、別の撮影プロセスは起動しない。

最後の0°直線は経路表から求める。標準設定では直線開始から45.21 mm後に観測し、145.21 mm後から新鮮な画像の多数決で初回方向を選ぶ。基準160 pxは画像上の暫定値で、センサーや床の位置の較正値ではない。方向に応じて最大10°・600 mmの目標方位を与え、白床・画像票などの条件で進入角を維持する。黒線の検出後は床値、向き、画像票に応じて横断・追従・再復帰へ移る。

青→黒が正常な間隔で成立した場合は黒から投影距離200 mmまで、標準PWM40で基準方位を保ちながら接近する。青候補後に黒が遅い・未検知の場合の青起点の総距離上限は標準350 mm。青未検知では距離フォールバックを使う。フォールバックでも接近完了後はATの接近を重複しない。この結果は物理的なボトル捕獲の証明ではなく、全体接続時の動作確認が必要。

## 標準と比較用の切替

| 項目 | 標準 | 比較用 |
| --- | --- | --- |
| 初回判定開始 | `LAP_DECISION_OFFSET_MM=145.21` | `100` |
| 進入角維持 | `LAP_FAR_ENTRY_POLICY=evidence` | `fixed60` |
| 遠い画像での追加角度 | `LAP_FAR_PEAK_DEG=10` | `12` |
| 暗床からの早期追従 | `LAP_DARK_ENTRY_EDGE=off` | `on` |

比較設定の優位性は実機で未確定。設定の読み出しは `robot_program/features/lap_recovery_options.py`、区間導出は `lap_straight_window.py`。床観測・診断記録は `robot_program/diagnostics/lap_recovery_observation.py` に分離している。床観測には早期復帰に必要な処理が含まれるので、本番から外してはいけない。

## 2026-11-15 実機比較

右コースの4走行では従来/evidence、早期/evidence、従来/fixed60の3回で青→黒とPWM40指令が確認された。早期/fixed60の1回は黒に届かず、画像票の一時不足後に保持を解除し距離フォールバックとなった。各1回であり、設定の優劣を証明しない。暗床からの早期追従は作動した実走1回で捕獲失敗となり、因果は未確定のため標準では無効。

PCのモック統合、最後の直線区間、構文と差分を確認。保存画像は間引かれており、実機の全票や変更後の軌道を再生できない。左コース、遠い初回位置、フォールバック後の全体工程、USB通信障害の再発については確認を要する。実行中のPiにはこの標準設定への変更をまだ転送していない。
